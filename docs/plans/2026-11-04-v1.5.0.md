# Version 1.5.0 implementation plan

The user authorized implementation and push. Keep the current Astro/React/Capacitor design and Django API.

1. Render a neutral startup screen on the server and until browser/native saved-session restoration finishes. Show an account skeleton only while dashboard data loads. Add a branded static 404 and unknown hash-route handling.
2. Add optional native device unlock using the OS biometric/device credential prompt. Offer it after the first authenticated app login, remember either choice, and expose enable/disable in app Security settings only. Store native sessions and preference in local secure storage. Lock enabled sessions on cold start and background/resume; cancellation stays locked with retry and sign-in recovery. No new login PIN.
3. Hide dashboard balance and account number together by default; one accessible eye toggles both. Hide virtual-card number and security code by default.
4. Issue persistent random numeric demo cards with VISA, RuPay or Mastercard selection. Support PIN-protected creation, freeze/unfreeze and replacement/network change. Migrate existing cards. These remain fictional cards without payment-network integration.
5. Retain two columns on mobile settings with vertically arranged content and adequate touch targets.
6. Add accurate notes for every published version from its tag range. Manual releases use matching notes (or generated commit notes for future versions). Generate an AltStore-compatible LiveContainer source from published IPA assets and update its stable URL automatically after publishing iOS releases. Add the source and instructions to README.
7. Verify API regressions, native unlock policy, source generation, TypeScript, web build and browser flows at mobile/desktop widths. Generate/sync native projects and build Android where tooling permits. Push main and publish v1.5.0 through the manual release workflow; report hosted and device checks separately.

Trade-offs: compact mobile tiles need more text wrapping but keep related options visible together. Device unlock is optional and local to the app/device; OS fallback preserves access when biometrics fail. Card replacement invalidates the previous demo number and requires explicit confirmation. A dedicated source branch avoids release automation modifying main or needing another deployment.
